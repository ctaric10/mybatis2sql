# 架构说明

## 目标

项目以单个 Java 源文件实现一个无第三方依赖的静态转换器：读取 MyBatis Mapper
XML，枚举动态 SQL 的代表性结构，并输出稳定、可审查的 SQL 文本。

## 处理流程

```text
发现 XML 文件
    ↓
安全解析 DOM（不加载外部 DTD）
    ↓
建立 namespace.id 全局片段索引
    ↓
递归渲染每条增删改查语句（文本节点先清理 -- 行注释）
    ↓
组合、限制并去重 SQL 变体
    ↓
规范化空白和参数占位符
    ↓
按相对目录写入 .sql 文件
```

## 核心组件

所有组件均为 `MybatisXmlToSql` 的内部类型，便于直接用 `javac` 编译。

- `MapperDocument`：保存 XML 路径、Mapper 根节点和 namespace。
- `FragmentRegistry`：以全限定 `namespace.id` 注册和查找 `<sql>` 片段。
- `Fragment`：保存片段节点、声明 namespace 和来源路径。
- `Renderer`：递归渲染 DOM 节点，并组合动态分支。
- `Variant`：同时保存 SQL 文本、分支说明和已经选择的 `if` 条件状态。

## 变体生成

顺序节点通过兼容的笛卡尔积组合。`if` 贡献包含与不包含两条路径，并以属性替换后、
去除首尾且压缩连续空白的 `test` 文本作为条件键。同一条语句中相同键的节点共享
状态；组合时如果两侧要求同一键分别为 true 和 false，该组合会被丢弃。这使 INSERT
列清单和 `VALUES` 中重复的判断只能同时包含或同时排除，也避免按 XML 节点数重复
计算同一个条件。

`choose` 贡献每个候选分支，`foreach` 贡献一个元素及两个元素的代表形式。由于循环
中的条件可能依赖 item/index，每个代表元素拥有独立的内部条件作用域。`where`、
`set` 和 `trim` 在子节点完成组合后应用包装规则，同时保留条件状态。

每当一个兼容组合真正加入结果集时都会检查 `mybatis2sql.maxVariants`，因此内存上限
依据实际可达的条件组合，而不是原始动态节点数量。超限时从语句根节点切换到线性
渲染：静态节点组成基线，每个唯一条件只与基线合并；相同条件键出现在不同 SQL
区段时，这些区段会合并到同一个 alternative。语句渲染完成后使用 `LinkedHashMap`
按规范化 SQL 去重，因此输出顺序可复现。

## SQL 行注释处理

`Renderer` 在普通枚举和超限后的逐条件渲染中，都会先对文本节点及 CDATA 调用
`stripLineComments`，然后才进行 include property 替换和相邻节点组合。提前处理很
重要：节点组合会裁剪边界空白，如果先拼接再清理，动态标签前的换行可能已经丢失，
`--` 就可能误吞原本位于下一行的动态节点或静态 SQL。

清理逻辑使用逐字符状态扫描，只在普通 SQL 状态下把 `--` 到当前行末的内容删除，
并保留 `\r`、`\n` 或 `\r\n` 行结束符。扫描器会识别单引号、双引号、反引号和块
注释区域，因此这些区域中的 `--` 会原样保留。`/* ... */` 只作为需要跳过扫描的
区域识别，不会从输出中删除。DOM 中的 XML 注释不是文本节点，渲染时会自然忽略。

## include 解析

目录范围内的 Mapper 会先被全部解析，再统一注册片段。片段记录自己的声明
namespace；渲染外部片段时，嵌套的无前缀 refid 使用该 namespace，而不是最初
语句的 namespace。

引用栈保存全限定片段 ID，可检测跨文档的 `A -> B -> A` 循环。注册阶段也会拒绝
重复的全限定 ID，防止输出依赖文件扫描顺序。

## XML 安全

解析器关闭外部实体和外部 DTD 加载，不会为了处理 Mapper 的 DOCTYPE 而访问网络
或本地外部资源。项目只读取输入 XML，并将结果写入调用方指定的输出位置。

## 测试策略

`MybatisXmlToSqlTest` 使用临时输出目录运行转换，并把结果与 `testdata` 中提交的预期
SQL 逐字节比较（换行符除外）。测试同时覆盖普通动态标签、跨目录 Mapper 引用，
重复 `if` 条件在普通枚举和超限降级中的列值配对，以及动态节点前后的多行 `--`
注释。注释测试还验证引号内的 `--` 和 `/* ... */` 块注释保持不变。GitHub Actions
会在受支持的 JDK 环境中重复执行同一组测试。
